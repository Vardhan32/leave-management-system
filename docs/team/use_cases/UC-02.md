# UC-02 Review a leave request

| | |
| --- | --- |
| Actor | HR admin (test account `admin@leavedesk.in`) |
| Workflow | W2 Review leave (approve / reject) |
| Requirements | FR-07, FR-08, FR-09, FR-10; rules BR1, BR2, BR3 |
| Automated in | `tests/team/e2e/specs/use-cases/uc02-review-leave.spec.ts` |
| Screen | `/approvals`, dialog "Review leave request" |

## Preconditions

1. The admin is signed in.
2. A request by an employee exists with status `pending` (each test creates its own through the API).
3. For an approval to succeed, the employee's remaining balance for that leave type and year is at least the request's days.

## Main flow (M1)

1. The admin opens Approvals; the Pending tab lists requests, newest first.
2. The admin finds the request (search by employee or reason) and selects **Review**.
3. The system shows the dialog: dates, working days, reason and the employee's balance with what remains after approval.
4. The admin enters a decision note (optional for approval).
5. The admin selects **Approve**.
6. The system sets the status to `approved`, stores reviewer, time and note, adds the days to `used_days`, closes the dialog and shows "<Name>'s request was approved."

## Alternative flows

| Id | Branches at | Flow |
| --- | --- | --- |
| A1 | step 4 | The admin leaves the note empty and approves. The request is approved with no note. |
| A2 | step 5 | The admin writes a note and selects **Reject**. Status becomes `rejected`, the note is stored, `used_days` does not change. |
| A3 | step 6 | After the decision, the request is no longer in the Pending tab and appears in the Approved tab. |

## Exception flows

| Id | Branches at | Condition | System response |
| --- | --- | --- | --- |
| E1 | step 5 | Reject with an empty note | "Add a short note before rejecting this request." The request stays pending. |
| E2 | step 5 | The employee's remaining days are fewer than the request needs (two pending requests of 8 days, the first already approved) | The server refuses with "This request exceeds the available balance." shown in the dialog. Request stays pending, `used_days` unchanged. (The dialog should also warn and disable **Approve** before the click, as it does for requests in the current year; for other years it does not: DEF-A3-01, test `UC-02-D1`.) |
| E3 | step 5 | The request was already decided or cancelled while the dialog was open | "Only pending requests can be reviewed." Status is whatever the other action set; `used_days` unchanged. |
| E4 | step 5 | The admin reviews their own request | "You cannot review your own leave request." Request stays pending. |

## Postconditions

| After | State |
| --- | --- |
| M1, A1 | `status = approved`, `reviewed_by` = admin, `reviewed_at` set, `review_note` as entered, `used_days` increased by the request's days exactly once. |
| A2 | `status = rejected`, note stored, `used_days` unchanged. |
| E1-E4 | The request keeps its previous status; `used_days` is unchanged; the dialog shows the message. |
