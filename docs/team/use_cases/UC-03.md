# UC-03 Cancel leave

| | |
| --- | --- |
| Actor | Employee (test account `demo@leavedesk.in`) |
| Workflow | Cancel (part of W1/W2 state changes) |
| Requirements | FR-11; rule BR3 |
| Automated in | `tests/team/e2e/specs/use-cases/uc03-cancel-leave.spec.ts` |
| Screen | `/leave`, dialog "Leave request", confirmation "Cancel this leave request?" |

## Preconditions

1. The employee is signed in.
2. The employee has a request that is `pending`, or `approved` and starting after today.

## Main flow (M1)

1. The employee opens My leave and selects **View** on a pending request.
2. The system shows the request with a **Cancel request** button.
3. The employee selects **Cancel request**; the system asks for confirmation.
4. The employee selects **Yes, cancel request**.
5. The system sets the status to `cancelled` and shows "Request withdrawn. You can apply again any time."

## Alternative flows

| Id | Branches at | Flow |
| --- | --- | --- |
| A1 | step 1 | The request is approved and has not started. After confirming, the days return to the balance (`used_days` decreases) and the message is "Request cancelled. Those days are back in your balance." |
| A2 | step 4 | The employee selects **Keep it**. The dialog closes and nothing changes. |

## Exception flows

| Id | Branches at | Condition | System response |
| --- | --- | --- | --- |
| E1 | step 2 | The leave has already started or ended | No **Cancel request** button is shown. A direct API call is refused with 409 "Leave that has already started cannot be cancelled." Status unchanged. |
| E2 | step 2 | The request is rejected (or already cancelled) | No cancel button; the API answers 409. Status unchanged. |

## Postconditions

| After | State |
| --- | --- |
| M1 | `status = cancelled`; `used_days` unchanged (a pending request never reserved days). |
| A1 | `status = cancelled`; `used_days` reduced by the request's days (never below zero). |
| A2, E1, E2 | Status and `used_days` unchanged. |

Known behaviour found while reading the source (not a test flow): a request that starts today can be created but, pending or not, cannot be cancelled (weakness WK-04 in `tests/team/api/reports/endpoint_weaknesses.md`).
