# UC-01 Apply for leave

| | |
| --- | --- |
| Actor | Employee (test account `demo@leavedesk.in`) |
| Workflow | W1 Apply for leave |
| Requirements | FR-01, FR-02, FR-03, FR-04, FR-05; rules BR1, BR4 |
| Automated in | `tests/team/e2e/specs/use-cases/uc01-apply-leave.spec.ts` |
| Screen | `/leave`, dialog "Request time off" |

## Preconditions

1. The employee is signed in.
2. The leave types and the employee's balance for the year exist (Casual 12, Sick 10, Earned 15 days a year; the balance row is created when first read).
3. For the chosen dates the employee has no pending or approved request.

## Main flow (M1)

1. The employee opens My leave and selects **Request leave**.
2. The system shows the dialog with the leave type preset to Casual.
3. The employee picks the leave type, a start date, an end date and enters a reason of at least 10 characters.
4. The system shows the working-day count (weekends are skipped).
5. The employee selects **Send request**.
6. The system validates the request, stores it as `pending`, closes the dialog and shows "Request sent. Your manager will review it shortly."

## Alternative flows

| Id | Branches at | Flow |
| --- | --- | --- |
| A1 | step 3 | The employee chooses another leave type (Earned). The request is stored with that type. |
| A2 | step 3 | The range runs over a weekend (Friday to Monday). Only the two weekdays count, so the request is for 2 days. |
| A3 | step 1 | The employee opens the dialog from the **Plan a break** link instead of the button. The rest is the same. |

## Exception flows

| Id | Branches at | Condition | System response |
| --- | --- | --- | --- |
| E1 | step 5 | End date is before the start date | "The end date cannot be before the start date." Dialog stays open, nothing stored. |
| E2 | step 5 | Reason shorter than 10 characters | "Add a little more detail (at least 10 characters)." Nothing stored. |
| E3 | step 5 | Working days exceed the remaining balance (13 casual days against 12) | A yellow warning "needs 13 days, but you only have N days" shows while typing (N is the *current* year's balance; DEF-A3-01 records that it should use the year of the dates). After sending, the server answers "Only 12 day(s) of Casual Leave remain for <year>." Nothing stored. |
| E4 | step 5 | Dates overlap the employee's own pending or approved request | "You already have a pending or approved request that overlaps these dates." Still one request, no duplicate. |
| E5 | step 5 | Start date is in the past | "Leave cannot start in the past." (answered by the server; the form itself does not check it). Nothing stored. |

## Postconditions

| After | State |
| --- | --- |
| Success (M1, A1-A3) | One new `LeaveRequest` with status `pending`, `days` equal to the weekdays in the range. `LeaveBalance.used_days` is **unchanged** (pending requests do not reserve days). |
| Any exception (E1-E5) | No new request exists for the entered dates. `used_days` unchanged. The dialog is still open with the message visible. |
